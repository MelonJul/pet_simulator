# 동작과 게임 모드 · 4.0

## 7일치 시뮬레이션

기존 반려동물 선택 → 홈쇼핑 → 아침/점심/저녁 급여와 오전/오후 각각 2회 돌봄 → 7일 평가를 유지합니다. 방의 친구를 누르면 상태창을 열 수 있습니다. 관찰·인벤토리·일지·가이드북·가격 근거는 무료입니다. 물품 추가 주문은 해당 게임에 저장된 기준가의 110%이며 반복해서 인상하지 않습니다.

식사·음수·일반 배변은 랜덤 사건과 별도의 동작입니다. 식사 또는 수분이 0이 되면 다른 회복이나 동작을 진행하기 전에 종료합니다. 위험한 상태에서는 새로운 랜덤 사건을 미루고 필요한 돌봄을 할 기회를 줍니다.

## 돌발 상황 체험

시작 화면에서 모드를 선택하고 동물을 고른 뒤 사건 목록으로 이동합니다. 모든 챕터를 처음부터 선택할 수 있고, 완료 여부는 **개체 ID + 사건 ID**로 기록합니다. 목록의 카드는 선택한 개체가 포함된 썸네일, 제목, 미체험/완료 표시를 제공합니다.

| 챕터 | 포함 사건 |
|---|---|
| 우리 집에 온 첫날 | 새집 적응, 첫 식사·음수, 첫 대변·소변, 고양이 화장실 밖 소변/개 패드 밖 실수 |
| 집 안의 작은 소동 | 고양이의 물컵·유리컵·화분·소파, 개의 신발·쓰레기통 |
| 마음을 알아가는 시간 | 놀이 요청·장난감 취향, 고양이의 상자·숨기, 개의 초인종·줄 당김·혼자 있을 때 문 긁기 |
| 갑자기 달라진 행동 | 식사·활동 변화, 반복 긁기, 배뇨 패턴 변화, 걸음 변화, 배뇨 곤란 |
| 예상하지 못한 지출 | 낡은 인형의 사용 중지·교체 계획, 삼킴 의심, 추가 진료 평가 |

종에 맞지 않는 사건은 목록에서 제외합니다. 사건을 직접 선택해도 챕터의 도입 이야기를 보여줍니다. 필요한 물품, 환경, 안정된 상태와 100만 원의 게임 예산을 준비한 별도 게임 상태에서 시작합니다. 첫 식사/음수/놀이 사건은 실제 돌봄 함수를 실행해 재고·회복·반응을 기록합니다. 다른 사건은 짧은 상황 동작 뒤 해당 사건을 실행합니다.

전체 화면 이미지는 자동으로 닫히지 않습니다. 닫기 뒤 **발생 사실 / 가능한 이유 / 대응 선택**만 표시하고, 대응 결과는 피드백·일지·체험 결과 화면에 남깁니다. 결과에서 다시 체험하기, 다음 사건, 사건 목록으로 이동할 수 있습니다. 다음 사건은 종별 필터를 적용한 챕터 순서입니다. 마지막 사건에서는 목록으로 이동합니다.

## 모드별 저장

- 시뮬레이션: 기존 `PetData.CONFIG.saveKey`를 유지합니다.
- 체험: `first-together-experience-v1`에 완료 표시, 선택 개체, 현재 체험 상태, 최초 대변/소변 안내 여부를 저장합니다.
- 체험의 지출·상태·실패·일지는 시뮬레이션 저장을 수정하지 않습니다.
- 체험을 반복할 때 상태와 예산은 새 프리셋을 만들지만 최초 배변 안내 기록은 유지합니다. 처음 안내한 대변/소변을 다시 선택하면 동작과 일지, 결과만 표시합니다.
- 목록의 **체험 기록 새로 시작**은 확인 후 체험 저장만 초기화합니다. 새 시뮬레이션은 해당 저장의 최초 안내만 초기화합니다.

## 동작과 한 번만 적용하는 규칙

`runtime.js`의 `command()`는 실제 돌봄을 한 번 실행한 뒤 `flow.queue`에 표시할 동작과 사건을 저장합니다. 동작이나 사건이 남아 있으면 다른 돌봄 명령을 거절합니다. UI에서도 동작 중 배경 클릭과 키 조작을 차단합니다.

`motions.js`는 게임 수치·재고를 쓰지 않습니다. 선택한 캐릭터의 원본 상태 PNG를 몸·머리·입·혀·앞발 레이어로 표시합니다. `anchors`의 입 위치를 실제 그릇 요소 좌표에 맞춥니다. 방 꾸미기로 옮긴 그릇도 같은 계산을 사용합니다.

| 경과 | 연출 |
|---|---|
| 0ms | 그릇 또는 배변 장소로 이동 |
| 650ms | 자리 잡기, 몸/머리 레이어 준비, 음식·수면 표시 |
| 1,050ms | 고개 내리기 또는 배변 자세 |
| 1,450ms | 씹기/혀 움직임, 사료 감소/물결 |
| 3,300ms | 마무리 반응 또는 고양이의 앞발 모래 덮기 |
| 4,400ms | 기본 자세 복귀 후 대기열의 다음 동작/사건 |

개와 고양이의 입 위치·고개 높이·음수 속도가 다릅니다. 개의 소변은 개체 설정에 따라 다리 들기와 쪼그리기를 구분하며 성별이나 질병을 추정하지 않습니다. 청소는 쌓인 대변/소변 흔적을 제거합니다. 화장실·패드가 없으면 바닥 흔적으로 기록합니다. 물 교체에 이은 실제 음수는 추가 행동 횟수가 없으며, 마시지 않았으면 회복·물 소모·마시는 연출을 하지 않습니다.

동작 완료에는 고유 번호가 필요합니다. 같은 완료 콜백은 두 번 적용되지 않습니다. 새로고침은 이미 적용한 급여를 반복하지 않고 저장된 표시 동작을 재개합니다. 배변의 흔적·청결·일지는 완료 시 한 번만 반영합니다. 최초 안내는 동작이 끝난 후 표시합니다. 시뮬레이션에서는 교육으로, 체험에서는 장면 이미지부터 이어집니다. 일반 배변 교육은 랜덤 사건 횟수와 사건 대응 점수에서 제외합니다.

## 조정 지점

| 파일 | 조정 내용 |
|---|---|
| `dist/event-data.js`의 `CONFIG` | `chance:0.62`, `minPerDay:2`, `maxPerDay:3`, 기본 재발 간격 3일, 하루 한 번 심각 사건 추첨 0.025, 중단을 미루는 식사/수분 임계값 32 |
| `dist/runtime.js` | 체크포인트·보완 발생·대기열·프리셋·배변 주기·저장 분리 |
| `dist/scenarios.js` | 새 사건, 종별 대상, 물품 손실, 대응, 설명, 관련 가이드, 챕터·도입, `demoMotion` |
| `dist/motions.js` | 개체별 입 앵커, 장소 좌표, 단계별 시간과 동작 |
| `dist/modes.css` | 머리·입·혀·앞발·수면·사료·배변 흔적·체험 화면 |
| `dist/event-ui.js` | 전체 화면 이미지와 세 항목 설명, 실제 소모 정보만 표시 |

새 사건을 자동 발생시키려면 `weight(state, pet, context)`를 0보다 크게 반환하도록 설정합니다. 새 건강 시나리오는 체험용으로 제공하며 무조건 랜덤 발생시키지 않습니다. 기존 건강 사건의 연속 기록 조건과 희귀 사건 제한을 유지합니다. `CHAPTERS[].events`에 ID를 넣으면 종별 필터를 적용한 체험 카드와 다음 사건 흐름에 연결됩니다. `demoMotion`은 `feed`, `water`, `play`, `stool`, `urine`을 지원합니다.

교육 안내의 의료 문구는 병명을 진단하지 않습니다. 배뇨 불가와 삼킴 의심은 즉시 병원 연락을 안내하며 기다림이나 임의 약물로 해결하지 않습니다. 상세 근거는 `scenarios.js`의 `SOURCES`, 게임 가이드북 및 `EVENTS.md`에 있습니다.

검사는 README의 명령으로 실행합니다. DOM 시간·좌표·UI 핸들러 검사는 실제 브라우저에서의 픽셀 품질을 보장하지 않습니다.
